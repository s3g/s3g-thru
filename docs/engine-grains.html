Grains

Grains launches overlapping, windowed readers from a moving, frozen, random, or sliced source position. It can also reorder equal source regions from quietest to loudest. Keyboard notes transpose the grains while Speed moves the source trajectory independently.

Controls edit the focused instrument. Instrument mode sets its lane and voice budget: eight voices in Single, four per part in either dual mode, or two per part in Quad. Quad omits stack controls because each part has one lane.

Good for: freezes, clouds, independent time/pitch motion, stereo spray, regular or scattered textures, rhythmic doublets, stutters, shrinking grain trains, and energy-ordered phrases.

Pages and navigation

Set Algorithm to Grains. Up first opens the shared Pads & Scale and Amp Envelope pages, followed by Stack Path, Grains Main, Grains Cloud, and Grains Process. Choose DRAW to add the editable Path Editor.

The controls common to every playback engine are documented in the shared Engine page table. Travel Envelope and Live Memory are also available in the Play page group. The sections below cover Grains-specific controls.

Travel Envelope

Travel Envelope changes source travel during each note, independently of keyboard pitch and the amp envelope. It multiplies Engine SPD; Stack Path still controls which sample lanes are blended. Each voice has its own clock. In Scan mode, use positive rates to move forward, zero to dwell, or negative rates to move backward. Freeze and random-origin modes can deliberately hide some of this movement.

Live Memory

Live Memory is available in Grains, Weave, Glitch, Cutups, Pulsar and Texture. It lets this engine read a continuously recorded stereo window instead of a loaded file. Open LIVE MEMORY in the Play page group. FILE keeps the ordinary four-lane samples; IN reads Move’s selected mic or line input. PT A–D read an available instrument part. Self-routing and feedback cycles are rejected. The loaded files remain available when you return to FILE.

KnobDisplayRangeWhat it controls
1SRCFile / In / PT A–DSource. Part feeds are after that part’s insert effects and strip, before its level, mute, blend and shared returns.
2BACK10–10000 msHow far the read window sits behind newly arriving audio.
3WIND50–12000 msRequested window length. Window and lookback are bounded together by available history; the waveform reports the actual window.
4FRZEOff / OnFreeze the captured history. Loop toggles this from any page for the focused Live Memory instrument. A recalled frozen source fills its empty memory before freezing.
5GAIN0–2×Live-source playback and capture gain. Input capture also follows the recording input gain.
6SAVEActionFreeze and archive the current stereo window in Thru’s recordings. Load the saved window into the selected lane and return SRC to FILE after loading completes.
7–8Reserved□Unavailable.

Live Memory is one source per receiving part, so stack navigation and file-lane gains show unavailable squares. POS, FLD, grain controls and keyboard pitch still shape the window. Grains retain their birth position in recorded history rather than chasing the writer. Grain duration is bounded to prevent reading overwritten memory; longer windows and lookbacks leave less room for long grains. Part feeds add one audio block of latency.

Synth into grains: choose Shared Dual, put a synth such as TABLE or FM on A and this engine on B, then set B SRC to PT A. Play A to supply audio and B to process it. Blend toward B to hear only the processed result; A continues feeding it. Start with WIND 1000 ms and BACK 250 ms.

Clips and projects recall Live Memory settings and recorded changes, but the rolling audio itself is temporary. Use SAVE before exporting a project or collection when its sound must be repeatable. A part copy carries the Travel Envelope while keeping the destination part’s Live Memory routing.
